## 实施目标

把 Anthropic Messages API 的 `output_config.effort` 无损转发到所有实际请求上游：

- Responses：`reasoning.effort`
- Responses input_tokens：`reasoning.effort`
- Chat Completions fallback：`reasoning_effort`

支持项目锁定 Anthropic SDK 0.115.0 定义的 `low | medium | high | xhigh | max | null`。不转换旧 `thinking.budget_tokens`，不按模型猜测可用等级；上游模型不支持时保留其原生错误。

## 设计

1. 在 `src/core/ir.ts` 增加协议无关的 `ReasoningEffort` 类型及 `CanonicalRequest.reasoningEffort?`，使主 Responses、token counting 与 Chat fallback 共用同一语义，避免把 Anthropic wire 字段塞入 provider extension。
2. 在 Anthropic wire 类型中增加 `output_config`；解码器只抽取并精确校验 `effort`：
   - 五个字符串和显式 `null` 合法；
   - 缺失 `output_config` 或缺失 `effort` 表示不设置；
   - 非对象、非法枚举或错误类型在任何上游调用前返回现有 Anthropic 400；
   - `output_config.format` 不映射为 effort，也不在本次宣称实现结构化输出。
3. 在 Responses 编码器中把 canonical effort 合成为 `reasoning.effort`。保留 `/v1/responses` 现有完整 `reasoning` 对象（例如 `summary`、`context`）的同协议回放；发生组合时只覆盖 `effort`，不丢其他字段。
4. 在 input_tokens 编码器中复制生成后的 `reasoning`；在 Chat 请求类型及编码器中输出顶层 `reasoning_effort`。`app.ts` 的流式和非流式路径共用这些编码器，无需增加路由分支。

## 测试驱动增量

1. 先写失败测试：
   - adapter 表驱动覆盖五档、`null`、缺失；
   - 非法 `output_config`/effort 被拒绝；
   - Responses、input_tokens、Chat 三种 wire 输出正确；
   - OpenAI 自身完整 `reasoning` 回放不回归。
2. 运行定向单测确认 RED，再实现 canonical 类型、Anthropic 解码和三个上游编码器，运行定向单测至 GREEN。
3. 扩展现有集成抓包测试，各用一个代表值验证：Anthropic 非流式、流式、count_tokens、Responses→Chat fallback；另用一个非法值验证 HTTP 400 且零上游调用。
4. 更新 `docs/compatibility.md`（必要时同步 README 的兼容范围），记录五档映射、`null`/缺失语义、三条上游路径及 `format` 不在本次范围。无需新 ADR，因为现有 canonical gateway ADR 已覆盖该决策。
