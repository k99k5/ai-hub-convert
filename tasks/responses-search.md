# Responses 搜索兼容工作

目标：保持网关 DuckDuckGo 执行搜索，补齐 Responses 客户端可实现的搜索协议；Anthropic 继续复用现有搜索循环。

依据：OpenAI 官方 Web Search 指南、流式事件参考、项目 OpenAI SDK 7.3.0 类型，以及现有搜索循环、Anthropic 搜索回放与 Responses 输出限额测试。

- [x] 确认执行方式、请求/响应/流式协议缺口及现有复用入口。
- [x] 请求：搜索工具选择、来源 include、调用次数、上下文大小、位置和域名约束；无法实现的离线/图片语义明确拒绝。
- [x] 输出：JSON 搜索调用、SSE 生命周期、来源与准确链接引用、搜索历史回传。
- [x] 验证：正常、空结果、边界、限额、取消、分块引用和多轮兼容测试。
- [x] 文档：参数映射及明确的能力限制。
- [x] 独立代理审查。

方案：复用 WebSearchSession、DuckDuckGo provider、ResponsesStreamEncoder 和 StreamOutputLimiter。搜索进度通过已有规范事件通道传递，网关搜索项由 Responses 编码层生成；不新增依赖、状态存储或上游原生搜索模式。

风险：流式输出索引必须保持稳定；搜索结果和新增引用受既有内存限额保护；普通同名函数不能被误判为内置搜索。搜索来源与引用不等价，仅对文本中实际引用的已检索链接生成注解。

验证命令：使用项目本地工具入口执行 Vitest、TypeScript 和 Biome，避免当前 pnpm 11 与项目 pnpm 10 的环境冲突。回滚可撤回本次代码和文档变更，无配置或数据迁移。
